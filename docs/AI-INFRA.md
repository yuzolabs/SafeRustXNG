# AIエージェントの情報取得層としてのRustXNG

RustXNGは、エージェントが必要な情報を検索し、出典URLと短い本文を取得するための基盤です。
モデルに渡す情報を必要な範囲に絞り、知識の更新を検索で補うことを目指します。

## 基本の使い方

[READMEの導入指示](../README.ja.md)をエージェントへ渡してください。
既存サービスを再利用し、新しく起動する場合はloopbackに限定します。
このチェックアウトの既定ポートは29483です。旧版を含む移行手順は[こちら](PORT-MIGRATION.md)です。

```bash
SEARXNG_PORT=29483 rustxng --bind 127.0.0.1 --port 29483
# 別のターミナルから
curl --fail --get 'http://127.0.0.1:29483/search' \
  --data-urlencode 'q=tokio runtime documentation' \
  --data 'format=json' --data 'max_results=5'
```

検索語は選択した外部検索エンジンへ送信されます。ローカル動作は検索語の外部送信を防ぐ意味ではありません。
多数の検索先はAPIキーなしで使えますが、認証付きプロバイダーは別途契約・設定が必要な場合があります。
汎用XPathエンジンを含む計78個のHTML取得エンジンは削除済みであり、残っている非HTML・内部JSON API等のエンジン構成は公式API限定や利用規約への適合を保証するものではありません。

## 小さなレスポンスから始める

最初は`max_results`とドメイン指定を使って対象を絞ります。
取得したJSONから`title`・`url`・`content`だけをモデルへ渡す例はREADMEにあります。
サーバー側の返却項目指定や、厳密なtokenizer別の予算は未実装です。

検索結果ページのHTML本文取得（旧`include_raw_content=1`および`raw_content`フィールド）とHTMLクローラー（旧`rustxng-index crawl`）は削除されました。旧クエリパラメータが渡された場合も無視され、結果URLへの通信は行いません。`/search`および`/research`は検索エンジン（API・フィード）が返す`content`（要約）のみを使用します。
文字数はトークン数ではなく、検索結果を取得できたことだけで内容の正確さは保証されません。

## 品質と可用性を測る

検索先の停止・ブロック・形式変更により、HTTP 200でも有用な結果がない場合があります。
エンジンごとの期限、サスペンド、空結果が続いた場合の休止処理で対処します。
`/healthz`はプロセスの応答確認であり、外部検索の成功確認ではありません。

[SealQA測定](SEALQA.md)では、LLMなしの検索で参照ページへの到達率と応答時間を記録しました。
これは回答の正解率とは別の指標です。[以前のベンチ](BENCHMARK.md)とはデータセットや条件が異なります。
いずれも汎用XPathを含む計78個のHTML取得エンジンおよび結果ページHTML取得を削除する前の履歴スナップショットです。エンジン削除前後での同時期・同一環境の比較や商用プロバイダーとの再比較は行っておらず、履歴数値を現在の性能保証として扱うことはできません。

## 現在の安全性と監査

[2026-11-02の監査](AUDIT-2026-11-02.md)には、当時のコミットに対するSSRF判定、
危険なURLスキーム、本文サイズ制限、キャッシュ分離、依存関係などの指摘があります。
監査ログは履歴であり、現在の全機能が安全であることを保証するものではありません。
結果ページの本文取得機能は削除されましたが、外部公開の前に指摘と修正状況を確認してください。

通常CIのテスト・Clippyに加え、最低Rust版と各OSでのローカル導入経路を検証します。
依存監査については[SECURITY.md](../SECURITY.md)を参照してください。
