## 方針

SafeRustXNGを、AIエージェントが導入してすぐ使える検索基盤として整える。
品質は検索精度、根拠と来歴の保持、鮮度、返却トークン量、応答時間で評価する。
モデルが暗記する情報を増やすことに加え、必要な外部情報へ少量の出力で到達できるようにする。

## 現状

- Engine / EngineRequestはAPI認証ヘッダー・JSON・formに対応し、認証付きプロバイダーを追加できる。
- SearchResultにはauthor・published_dateがある。一方、投稿ID・作者ID・会話参照は型付きの共通項目ではない。
- max_resultsとドメイン絞込みはあるが、共通のfields指定・本文予算・モデル別token予算はない。
- 通常のランキング検索は上位件数を絞るので、新着監視の完全性を保証する用途にそのまま使わない。

## 3. 少ないトークンで根拠を返す

後方互換を維持した追加の出力形式を設計する。以下は候補名であり既存パラメータではない。

- fields: 必要な項目のみ返す。
- snippet_chars / total_content_chars: 各件・全体の文字数上限。
- passages: クエリに関係する段落を引用元URL・本文内位置とともに返す。
- tokenizer指定のtoken_budget: 対応tokenizerでのみ厳密に計数する。

文字数とトークン数を同一視しない。打切りをtruncated等で明示し、出典・安定IDは予算内でも保持する。
tokenizer未指定時は文字数・バイト数の制限を提供し、厳密なtoken保証を表示しない。

完了条件: SealQA等の参照ページ到達率を維持しながら、返却byte数・モデル別token数・
根拠段落の到達率・p95遅延を比較できる。要約だけを根拠原文として扱わない。
